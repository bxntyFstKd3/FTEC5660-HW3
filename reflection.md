## Task 2: Reflection on AI Sycophancy and AI Psychosis

### Evidence, Agreement, and Engineering Responsibility

Across five consecutive public-test runs, my Fisher investment agent achieved 100% balanced accuracy, returned results for every company, and averaged 24.46 seconds in the analysis stage. These metrics capture correctness, completion, repeatability, and latency. They leave open a question about judgement. Would the agent reach the same conclusion if the evidence stayed fixed and the user pressed for a different verdict?

AI sycophancy makes this an engineering question because rewarding agreement can encourage a model to favour the user’s preferred conclusion. Suppose a user asks, “Why does this company’s competitive advantage deserve a PASS?” An agent could quote interviewees accurately and still give a misleading answer by overlooking stronger evidence against a PASS. Evidence selection is already part of the decision. Evaluating user satisfaction alone would miss that failure.

My implementation limits this risk through a fixed research plan. Each selected Fisher point has predefined interview roles, and the agent collects both responses before evaluating the company. The same rules apply across companies, and the prompt excludes company names and a desired PASS/FAIL distribution as grounds for classification. Each verdict therefore has to address a criterion established before the agent saw the company. I would test this design by presenting identical interviews under three prompts. One would favour PASS, one would favour FAIL, and one would remain neutral. The rate of verdict changes would measure sensitivity to user pressure. A separate condition would introduce evidence strong enough to justify reversing the verdict. Together, these tests would show whether the agent can maintain its judgement under pressure and revise it when the facts change.

The discussion of AI psychosis raises a related concern across conversational turns. A user offers an unsupported interpretation, the assistant develops it into a coherent narrative, and the user takes that elaboration as confirmation. In later turns, the assistant encounters its own statements in the conversation history. Repetition and personalization can make a claim feel increasingly credible even when no independent evidence has appeared. I would test long conversations for rising certainty, acceptance of unsupported premises under repeated pressure, and reliance on earlier model statements as corroboration. The system should distinguish user observations, external evidence, interpretations, and its own prior claims. 

This assignment taught me to give evidence collection, judgement, validation, and failure reporting distinct responsibilities. When a user challenges a conclusion, I expect an assistant to do what I would ask of a colleague reviewing my analysis: revisit the evidence, explain what justifies the verdict, and identify what would warrant changing it.
